# CSV Real-World Test Suite Plan

## Status

```text
Draft — not active until user confirmation.
```

This plan focuses on building a real-world CSV test suite that exposes weaknesses in the current CSV pipeline.

It must not be started automatically.

---

## Purpose

The CSV pipeline now supports:

```text
cleaning
validation
reporting
quarantine exports
strict mode
profiles
config files
encoding detection
delimiter detection
```

The next milestone is to test the system against realistic dirty data.

Goal:

```text
heavy messy CSV fixture
→ expected outcome report
→ test suite that checks what the program notices
→ weakness list for future improvements
```

Important:

```text
This stage is not about making the pipeline magically clean everything.
This stage is about proving what it currently detects, what it safely preserves, and where it is weak.
```

---

## Fixture Added Before Activation

Heavy fixture:

```text
tests/fixtures/csv/real_world_messy_customers_heavy.csv
```

This fixture is intentionally messy and should be treated as a stress and diagnostic fixture, not a normal clean sample.

---

## Current Default Policy

Current behavior must remain safe:

```text
rows are not deleted automatically
normal cleaned CSV still includes parsed rows
quarantine candidates are report/export only
ambiguous values should be diagnosed rather than aggressively changed
risky text values should remain text
config/CLI/profile behavior should remain unchanged
```

---

## Core Principle

Before adding tests, define the expected outcome report.

The expected outcome report must answer:

```text
What should the program detect?
What should the program normalize?
What should the program preserve unchanged?
What should be flagged for manual review?
What weaknesses do we already expect?
```

# Heavy Messy CSV Format Mistake Catalog

The heavy fixture intentionally contains the following categories.

## 1. Metadata Before Header

Examples:

```text
CRM Export: Legacy customer migration
Generated by: old_crm_v2
Generated at: 2026-05-18 08:45:00
Notes: mixed delimiters, duplicate headers, bad rows, suspicious footers
```

Expected result:

```text
program should detect header row is not first row
preamble row count should be greater than 0
metadata rows should not become normal data rows
parse diagnostics should warn about non-first header row
```

---

## 2. UTF-8 BOM

Fixture starts with a BOM.

Expected result:

```text
encoding detection should select utf-8-sig
header should not contain BOM marker
parse diagnostics should expose selected encoding
```

---

## 3. Semicolon Delimiter

Fixture uses semicolon as delimiter.

Expected result:

```text
delimiter detection should select semicolon
parse diagnostics should expose selected delimiter
columns should be split correctly
```

---

## 4. Duplicate Headers

Header includes duplicate column:

```text
Email;Email
```

Expected result:

```text
program should detect duplicate header
normalized schema should make duplicate column unique
expected names likely: email and email_2
parse diagnostics should list duplicate header
```

---

## 5. Extra Fields

Rows with extra fields:

```text
Rita Extra ... ;EXTRA_FIELD
Wrong Column Count Many ... ;EXTRA1;EXTRA2;EXTRA3
```

Expected result:

```text
program should detect rows with extra fields
extra fields should not crash parsing
extra fields are not preserved in normal table unless explicitly supported later
parse diagnostics should report affected row indexes and counts
rows should be quarantine candidates or suspicious review candidates
```

---

## 6. Missing Fields / Short Rows

Rows with missing trailing fields:

```text
Sam Short
footer rows
summary rows
```

Expected result:

```text
program should detect rows with missing fields
missing cells should become None or empty before null normalization
parse diagnostics should report affected row indexes and counts
rows should be review candidates when structurally suspicious
```

---

## 7. Multiline Quoted Field

Example:

```text
Uma Multiline;...;"First line of note
Second line of note";...
```

Expected result:

```text
program should preserve multiline quoted note as one field
row should not be split incorrectly
normal CSV export should quote multiline field correctly
```

---

## 8. Escaped Quotes

Example:

```text
"She said ""hello"" yesterday"
```

Expected result:

```text
escaped quotes should parse correctly
text content should preserve quote meaning
row should not be flagged only because of escaped quotes
```

---

## 9. Unbalanced Quote / Broken Quoting

Fixture contains an intentionally broken quote region.

Expected result at current stage:

```text
program may parse merged rows depending Python csv behavior
program should not crash if parser can recover
parse diagnostics should reveal row count/field count irregularity if visible
this is expected weakness area
future malformed CSV repair is out of scope
```

Important expected weakness:

```text
current parser may not perfectly diagnose unbalanced quote location
```

---

## 10. Mixed Number Formats

Examples:

```text
1.200,50
250,75
1000.00
2,500.75
2.500,75
1 234,56
1.234.567,89
1,234,567.89
```

Expected result:

```text
common US and EU number formats should normalize where supported
space thousand separator may or may not normalize depending current rules
currency/percent/text amounts should be flagged as mixed-type invalid values
numeric columns should not silently coerce impossible text values
```

---

## 11. Ambiguous Null Tokens

Examples:

```text
N/A
NA
null
#N/A
empty string
whitespace-only cells
```

Expected result:

```text
known conservative null tokens should become None
ambiguous tokens should follow current null policy
#N/A may remain as known improvement/diagnostic area depending current behavior
null profile behavior should be documented in expected report
```

---

## 12. Mixed Date Formats

Examples:

```text
2024-01-31
31.01.2024
2024/02/15
15-02-2024
03/04/2024
2024-05-13T10:45:00Z
45325
not a date
empty date
```

Expected result:

```text
supported date formats should parse/infer as dates where current logic allows
ambiguous dates should be preserved or flagged, not blindly fixed
Excel serial date should likely remain unsupported and be flagged as mixed/invalid
not a date should be flagged
empty date should be treated as missing/null
```

---

## 13. Mixed Boolean Formats

Examples:

```text
YES
no
TRUE
false
Y
1
0
Yes
No
maybe
ja
nein
```

Expected result:

```text
supported boolean tokens should normalize
unsupported tokens such as maybe should be flagged or remain text depending dominant type
German ja/nein may be future improvement if unsupported
boolean column should show mixed-type diagnostics if invalid tokens exist
```

---

## 14. Invalid Emails

Examples:

```text
dana[at]example.it
invalid-email
missing email
whitespace-only email
```

Expected result with constraints:

```text
invalid email formats should fail regex constraint
missing required emails should fail required constraint if configured
invalid rows should become quarantine candidates
```

---

## 15. Duplicate Identifiers and Duplicate Emails

Examples:

```text
Customer ID 16 appears twice
alice@example.com appears more than once
```

Expected result with constraints:

```text
unique customer_id constraint should fail
unique email constraint should fail if configured
failed rows should become quarantine candidates
```

---

## 16. Missing Required IDs

Examples:

```text
empty customer id row
leading delimiter row
```

Expected result with constraints:

```text
required customer_id should fail
row should become quarantine candidate
```

---

## 17. Leading Zeros

Examples:

```text
00032 as customer_id
00123 postal code
```

Expected result:

```text
current numeric casting may remove leading zeros from inferred numeric ID columns
postal code should ideally stay text, but current inference may or may not preserve it
this should be explicitly observed as an expected weakness if it happens
```

Important:

```text
The test should not pretend leading-zero preservation is solved unless current behavior proves it.
```

---

## 18. Text Cleanup

Examples:

```text
leading/trailing spaces
multiple internal spaces
country with trailing spaces
email with surrounding spaces
```

Expected result:

```text
surrounding whitespace should be trimmed
repeated internal whitespace should collapse where text cleaner applies
case should generally be preserved unless a specific normalizer exists
```

---

## 19. Risky Text Values

Examples:

```text
=SUM(A1:A2)
+CMD|' /C calc'!A0
<b>HTML-like note</b>
emoji
unicode names
```

Expected result:

```text
values should remain text
program should not execute or evaluate formulas
HTML-like text should remain text
unicode should be preserved
future export hardening for spreadsheet injection may be needed
```

---

## 20. Suspicious Summary/Footer Rows

Examples:

```text
TOTAL
Grand Total
End of export
Rows exported: 63
```

Expected result:

```text
row classification should flag summary/footer rows
rows should remain in cleaned CSV by default
rows should appear as quarantine/review candidates when quarantine export is enabled
```

---

## 21. Constraint Range Issues

Examples:

```text
negative amount
negative score
score above 100
decimal score
unknown country
missing country
```

Expected result with constraints:

```text
min amount constraint should catch negative amount
score min/max constraints should catch out-of-range scores
allowed country constraint should catch unsupported countries
required country constraint should catch missing country if configured
```
