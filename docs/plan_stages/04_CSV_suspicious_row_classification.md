# CSV Suspicious Row Classification Plan

## Status

```text
Draft — not active until user confirmation.
```

This plan focuses on detecting suspicious CSV rows such as garbage lines, footer rows, summary rows, and comment-like rows.

It must not be started automatically.

---

## Purpose

Improve CSV diagnostics by identifying rows that are structurally parsed but unlikely to be normal data records.

Goal:

```text
CSV rows
→ canonical Table
→ suspicious row classification
→ diagnostic bundle reporting
→ future quarantine support
```

This plan is diagnostic-first. It should not remove, quarantine, or mutate rows yet.

---

## Problem

Real CSV exports often contain non-data rows mixed with data.

Examples:

```text
Report generated by System X
# comment row
TOTAL,,650.50
End of export
```

Current risk:

```text
non-data rows are treated as normal rows
quality reports may be misleading
type inference may be polluted
exports may preserve unwanted rows without warning
```

Expected behavior for this plan:

```text
rows remain in the table
suspicious rows are reported in diagnostics
future stages may quarantine or exclude them explicitly
```

# Stage D — Classification Heuristics

## Goal

Implement conservative heuristics for common suspicious rows.

Suggested heuristics:

```text
empty_row:
  all values are None or empty strings

comment_row:
  first non-empty value starts with #, //, or ;

summary_row:
  first non-empty value starts with TOTAL, SUM, SUBTOTAL, GRAND TOTAL

footer_row:
  first non-empty value contains END OF, GENERATED, EXPORT COMPLETE

garbage_row:
  row has one populated cell and does not match expected data patterns
```

## Expected Files

```text
data_processor/analysis/row_classification.py
data_processor/analysis/row_classification.md
tests/test_row_classification.py
tests/test_row_classification.md
log_protocol/04_CSV_suspicious_row_classification/004_classification_heuristics.md
```

## Acceptance Criteria

- Heuristics are conservative.
- Classifications include reason and confidence.
- Tests cover each classification.
- Normal rows are not over-classified.

# Stage G — Quarantine Policy Decision

## Goal

Decide whether suspicious row classification should affect row quarantine or export behavior.

Options:

```text
Option 1: diagnostics only, no row removal
Option 2: diagnostics + optional exclude from export
Option 3: diagnostics + quarantine candidate export
Option 4: automatic quarantine
```

Recommended for now:

```text
Option 1: diagnostics only, no row removal
```

Reason:

```text
automatic removal risks data loss
quarantine requires a dedicated row quarantine model and report export support
```

## Expected Files

```text
docs/design/suspicious_row_quarantine_policy.md
log_protocol/04_CSV_suspicious_row_classification/007_quarantine_policy_decision.md
```

## Acceptance Criteria

- Policy decision is documented.
- No automatic row removal is introduced.
- Future quarantine relationship is described.
