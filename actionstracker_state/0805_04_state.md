# Project State

## Current Phase

The project is currently in the foundation architecture phase.

The system supports a complete CSV-based data processing flow and now includes diagnostic, profiling, validation, and reporting foundations.

Current scope:

```text
well-formed or mostly well-formed CSV
→ canonical Table
→ cleaning
→ type inference
→ type-aware casting
→ schema metadata
→ profiling
→ validation
→ diagnostic reporting
→ CSV/JSON export
```

The project is not yet focused on broken-file recovery or hostile migration data.

# Current Known Assumptions

The CSV parser currently assumes mostly valid CSV grammar.

Meaning:

```text
consistent delimiter
readable encoding
properly escaped quotes
valid row structure
headers exist
```

It can handle:

```text
quoted commas
spaces before quoted fields with skipinitialspace
basic encoding fallback
header normalization
```

It does not yet fully handle:

```text
broken delimiters
mixed delimiters
bad encodings
partial rows
unescaped quotes
duplicate headers
garbage bytes
Excel-export corruption
schema drift
corrupted files
```

Those belong to later robustness stages.

Adapters only parse.

# Important Current Design Decision

The project should continue strengthening the canonical `Table` workflow before adding new formats.

Reason:

```text
CSV, Excel, JSON, SQL, and APIs should all reuse the same:
cleaners
inference
profiling
validation
reports
exporters
```

The stronger the foundation becomes now, the easier future format support becomes.
