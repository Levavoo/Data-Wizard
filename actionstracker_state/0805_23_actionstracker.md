Case 12 — Metadata Lines Before Header

Purpose:

verify how the current system behaves when a CSV export contains metadata lines before the real header

This is common in business exports.

Create:

New-Item examples\csv\metadata_before_header.csv
examples/csv/metadata_before_header.csv
Export generated by System X
Generated at: 2026-05-08
Department: Sales
customer_id,name,country,active,amount
1,Alice,Germany,true,100
2,Bob,France,false,250.50
3,Charlie,Italy,true,300

Run:

python scripts\run_csv_pipeline.py `
    examples\csv\metadata_before_header.csv `
    data\processed\metadata_before_header_clean.csv `
    --report-path data\processed\metadata_before_header_report.json

Inspect:

Get-Content data\processed\metadata_before_header_clean.csv
Get-Content data\processed\metadata_before_header_report.json

Expected current behavior:

The adapter will incorrectly treat:
"Export generated by System X"
as the header.

Likely cleaned output will have one column similar to:

export_generated_by_system_x

and later lines will become malformed/short/extra rows.

This is useful because it confirms the future need for:

header row detection
metadata preamble detection
parse diagnostics
tolerant CSV mode

Future desired behavior:

detect likely header row:
customer_id,name,country,active,amount

store pre-header lines as metadata/preamble warnings
parse actual table rows correctly

FAILURE

This is a common real-world CSV export pattern:

metadata/preamble lines
real header row
data rows

Your current adapter assumes:

first row = header

That is fine for simple CSV, but not enough for migration work.

Recommended fix

Add basic header row detection to CsvAdapter.

New behavior:

read all rows
→ find the most likely header row
→ store earlier rows as preamble metadata
→ parse from detected header row
Detection rule for now

Simple and deterministic:

choose the first row with the highest field count

For this file:

Export generated by System X                  → 1 field
Generated at: 2026-05-08                      → 1 field
Department: Sales                             → 1 field
customer_id,name,country,active,amount        → 5 fields
1,Alice,Germany,true,100                      → 5 fields

The first row with the highest field count is:

customer_id,name,country,active,amount

So it becomes the header.

Store metadata

Add this to table.metadata:

"header_row_index": 3
"preamble_rows": [
    ["Export generated by System X"],
    ["Generated at: 2026-05-08"],
    ["Department: Sales"]
]
