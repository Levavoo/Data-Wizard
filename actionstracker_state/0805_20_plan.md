Case 10 — Mixed-Type Column

Purpose:

detect columns with values like numbers + random text

Example:

customer_id,name,amount
1,Alice,100
2,Bob,unknown
3,Charlie,250.50
4,Diana,n/a

Expected for now:

amount → string or mixed-like later

This shows that later we may need a mixed inferred type or invalid-type diagnostics.

Case 11 — Garbage / Comment Lines

Purpose:

detect random non-table text inside a CSV file

Example:

customer_id,name,country
1,Alice,Germany
THIS IS A RANDOM NOTE LINE
2,Bob,France

Current behavior:

the note line will become a short row

This is not wrong technically, but we should later report it as suspicious.

Case 12 — Metadata Lines Before Header

Very common in exports.

Example:

Export generated by System X
Date: 2026-05-08
customer_id,name,country
1,Alice,Germany
2,Bob,France

Current system will incorrectly treat:

Export generated by System X

as the header.

Later fix:

header row detection
Case 13 — Footer / Summary Lines

Common in reports exported as CSV.

Example:

customer_id,name,amount
1,Alice,100
2,Bob,200
TOTAL,,300

Current behavior:

TOTAL row is treated as data

Later fix:

footer detection / suspicious row detection
Case 14 — Multi-Line Quoted Fields

Valid CSV.

Example:

customer_id,name,notes
1,Alice,"First line
second line"
2,Bob,"Normal note"

Python csv.reader should support this, but we should test it.

Case 15 — Escaped Quotes

Valid CSV.

Example:

customer_id,name,notes
1,Alice,"She said ""hello"""

Should parse as:

She said "hello"
Case 16 — European Decimal Numbers

Common in Germany/EU.

Example:

customer_id,amount
1,"1.000,50"
2,"250,75"

Current system likely treats this as string.

Later fix:

locale-aware numeric parsing
Case 17 — Weird Null Tokens

Example:

customer_id,name,email
1,Alice,-
2,Bob,NULL
3,Charlie,NIL
4,Diana,#N/A

Current support includes:

"", null, none, n/a, na, nan, -

But not yet:

NIL, #N/A
Case 18 — Whitespace-Only Cells

Example:

customer_id,name,email
1,Alice,"   "
2,Bob,"	"

Current pipeline should likely clean these to None only if text cleaning happens before null cleaning again. Right now null cleaning happens before text cleaning, so whitespace-only cells may become empty strings after text cleaning, not None. This is worth checking.

Recommended next order

Before building new features, test these three first:

1. mixed_type_column.csv
2. garbage_lines.csv
3. whitespace_only_cells.csv

Why these first:

mixed values → type inference weakness
garbage lines → parser diagnostics need
whitespace cells → pipeline ordering issue

The “random text in between values” case is best covered by:

garbage_lines.csv

and maybe:

mixed_type_column.csv
