# csv_adapter.py

## Purpose

`csv_adapter.py` reads CSV files and converts them into the internal `Table` model.

This is the first real ingestion adapter in the system.

Architecture:

```text
CSV File
→ CsvAdapter
→ Table
```

---

# Responsibilities

The CSV adapter is responsible for:

- validating the source file
- detecting encoding
- detecting delimiter
- reading CSV rows
- detecting the likely header row
- preserving pre-header metadata rows
- normalizing headers
- making duplicate headers unique
- handling empty headers
- aligning row values to schema columns
- building the schema
- building the internal table
- storing parser metadata

The adapter is NOT responsible for:

- cleaning values
- type inference
- validation
- transformations
- exporting

# Important Parser Design

The adapter uses:

```python
csv.reader
```

instead of:

```python
csv.DictReader
```

Reason:

`csv.DictReader` collapses duplicate headers because dictionary keys must be unique.

Example:

```csv
customer_id,name,name,country
1,Alice,Alicia,Germany
```

With `csv.DictReader`, one `name` value can overwrite the other.

Using `csv.reader` preserves all fields and allows the adapter to safely rename duplicate headers.

---

# Header Row Detection

Some CSV exports contain metadata lines before the real header.

Example:

```csv
Export generated by System X
Generated at: 2026-05-08
Department: Sales
customer_id,name,country,active,amount
1,Alice,Germany,true,100
```

The adapter now detects the likely header row.

Current heuristic:

```text
choose the first row with the highest field count
```

In the example above:

```text
Export generated by System X       → 1 field
Generated at: 2026-05-08           → 1 field
Department: Sales                  → 1 field
customer_id,name,country,...       → 5 fields
```

So this row becomes the header:

```text
customer_id,name,country,active,amount
```

---

# Preamble Rows

Rows before the detected header are preserved as metadata.

Example metadata:

```python
{
    "header_row_index": 3,
    "preamble_rows": [
        ["Export generated by System X"],
        ["Generated at: 2026-05-08"],
        ["Department: Sales"]
    ]
}
```

This keeps export metadata available for diagnostics without treating it as table data.

# Supported Encodings

Current fallback order:

```text
utf-8
utf-8-sig
cp1252
```

Purpose:

- support common Windows CSV files
- support BOM-based UTF files
- support legacy encodings

---

# Supported Delimiters

Current candidates:

```text
,
;
\t
|
```

Delimiter detection uses:

```python
csv.Sniffer()
```

Fallback delimiter:

```text
,
```

---

# Header Normalization

Current normalization rules:

```text
trim whitespace
lowercase
replace spaces with underscores
empty header → unnamed_column
duplicate header → add numeric suffix
```

Examples:

```text
" Customer ID "
→ "customer_id"

""
→ "unnamed_column"

"name", "name"
→ "name", "name_2"
```

---

# Duplicate Header Handling

Duplicate headers are made unique by adding a suffix.

Example:

```csv
customer_id,name,name,country
```

becomes:

```text
customer_id
name
name_2
country
```

If there are more duplicates:

```text
name
name_2
name_3
```

This preserves all source data.

---

# Empty Header Handling

Empty headers are converted to:

```text
unnamed_column
```

Example:

```csv
id,,country
```

becomes:

```text
id
unnamed_column
country
```

If multiple empty headers exist:

```text
unnamed_column
unnamed_column_2
```

---

# Row Handling

Rows are aligned by position.

Example headers:

```text
customer_id
name
country
```

Example row:

```csv
1,Alice,Germany
```

becomes:

```python
{
    "customer_id": "1",
    "name": "Alice",
    "country": "Germany"
}
```

---

# Short Row Handling

If a row has fewer values than headers, missing values become:

```python
None
```

Example:

```csv
customer_id,name,country
1,Alice
```

becomes:

```python
{
    "customer_id": "1",
    "name": "Alice",
    "country": None
}
```

---

# Extra Field Handling

Current behavior:

```text
extra fields beyond the known headers are ignored
```

Example:

```csv
customer_id,name
1,Alice,Germany
```

becomes:

```python
{
    "customer_id": "1",
    "name": "Alice"
}
```

Future parser diagnostics should report ignored extra fields.

---

# Row Values

Rows are initially stored as raw strings or `None`.

Example:

```python
{
    "customer_id": "1001",
    "country": "Germany",
    "email": None
}
```

Important:

No type conversion happens here.

This is intentional.

Type inference and type-aware casting belong to later pipeline stages.

# Main Methods

## `read()`

Main adapter entry point.

Flow:

```text
validate file
→ detect encoding
→ detect delimiter
→ read all rows
→ detect header row
→ preserve preamble rows
→ normalize headers
→ build schema
→ read data rows
→ align row values
→ build table
→ store metadata
→ return Table
```

---

## `_detect_encoding()`

Tries multiple encodings until one succeeds.

Raises:

```python
ValueError
```

if decoding fails.

---

## `_detect_delimiter()`

Uses `csv.Sniffer()` to detect delimiter.

Fallback:

```text
,
```

---

## `_read_rows()`

Reads all CSV rows using `csv.reader`.

This preserves:

- duplicate headers
- quoted values
- quoted commas
- row structure

---

## `_detect_header_row_index()`

Detects the likely header row.

Current rule:

```text
first row with highest field count
```

This supports CSV files with preamble metadata before the real table.

---

## `_normalize_header()`

Converts one external header into an internal name.

Current rules:

- trim
- lowercase
- spaces → underscores
- empty header → `unnamed_column`

---

## `_normalize_headers()`

Normalizes all headers and makes duplicates unique.

Example:

```python
["name", "name", ""]
```

becomes:

```python
["name", "name_2", "unnamed_column"]
```

---

## `_build_schema()`

Creates a `Schema` object from CSV headers.

Creates one `Column` per header.

---

## `_normalize_row()`

Converts a raw CSV row list into a normalized row dictionary.

Maps:

```text
column position
→ normalized header
```

---

# Metadata

The adapter stores parser metadata on the table.

Current metadata:

```python
{
    "source_format": "csv",
    "encoding": "utf-8",
    "delimiter": ",",
    "header_row_index": 0,
    "preamble_rows": []
}
```

For files with preamble rows:

```python
{
    "source_format": "csv",
    "encoding": "utf-8",
    "delimiter": ",",
    "header_row_index": 3,
    "preamble_rows": [
        ["Export generated by System X"],
        ["Generated at: 2026-05-08"],
        ["Department: Sales"]
    ]
}
```

This metadata is included in diagnostic reports.

from data_processor.adapters.csv_adapter import CsvAdapter

- implicit null handling
- automatic datetime parsing
