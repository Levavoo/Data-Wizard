# csv_adapter.py

## Purpose

`csv_adapter.py` reads CSV files and converts them into the internal `Table` model.

This is the first real ingestion adapter in the system.

Architecture:

```text
CSV File
→ CsvAdapter
→ Table
```

---

# Responsibilities

The CSV adapter is responsible for:

- validating the source file
- detecting encoding
- detecting delimiter
- reading CSV rows
- detecting the likely header row
- preserving pre-header metadata rows
- normalizing headers
- making duplicate headers unique
- handling empty headers
- aligning row values to schema columns
- building the schema
- building the internal table
- storing parser metadata
- attaching structured parse diagnostics

The adapter is NOT responsible for:

- cleaning values
- type inference
- validation
- transformations
- exporting

---

# Parse Diagnostics

The adapter now attaches a structured parser diagnostics dictionary to:

```python
table.metadata["parse_diagnostics"]
```

This section records structural parsing observations only.

It may include:

- detected header row index
- preamble row count
- rows with extra fields
- rows with missing fields
- duplicate normalized headers
- empty header positions
- detected delimiter
- detected encoding
- parser warnings

Example:

```python
{
    "header_row_index": 1,
    "preamble_row_count": 1,
    "rows_with_extra_fields": [3],
    "extra_field_count": 1,
    "rows_with_missing_fields": [2],
    "missing_field_count": 1,
    "duplicate_headers": ["name"],
    "empty_headers": [3],
    "delimiter": ",",
    "encoding": "utf-8",
    "warnings": [
        "Header row was not the first source row.",
        "One or more rows contain extra fields."
    ]
}
```

Important:

Parse diagnostics do not clean, validate, quarantine, or transform data.

# Important Parser Design

The adapter uses:

```python
csv.reader
```

instead of:

```python
csv.DictReader
```

Reason:

`csv.DictReader` collapses duplicate headers because dictionary keys must be unique.

Example:

```csv
customer_id,name,name,country
1,Alice,Alicia,Germany
```

With `csv.DictReader`, one `name` value can overwrite the other.

Using `csv.reader` preserves all fields and allows the adapter to safely rename duplicate headers.

---

# Header Row Detection

Some CSV exports contain metadata lines before the real header.

Example:

```csv
Export generated by System X
Generated at: 2026-05-08
Department: Sales
customer_id,name,country,active,amount
1,Alice,Germany,true,100
```

The adapter detects the likely header row.

Current heuristic:

```text
prefer the first row with more than one field
require at least one following row with the same field count
fall back to row 0 if no stronger candidate exists
```

Rows before the detected header are stored as preamble rows.

---

# Row Handling

Rows are aligned by position.

Short rows are padded with `None`.

Extra fields beyond the known headers are still ignored in the canonical row, but they are now reported in `parse_diagnostics`.

---

# Metadata

The adapter stores parser metadata on the table.

Current metadata:

```python
{
    "source_format": "csv",
    "encoding": "utf-8",
    "delimiter": ",",
    "header_row_index": 0,
    "preamble_rows": [],
    "parse_diagnostics": {...}
}
```

This metadata is included in diagnostic reports.

# Main Methods

## `read()`

Main adapter entry point.

Flow:

```text
validate file
→ detect encoding
→ detect delimiter
→ read all rows
→ detect header row
→ preserve preamble rows
→ normalize headers
→ build parse diagnostics
→ build schema
→ read data rows
→ align row values
→ build table
→ store metadata
→ return Table
```

---

## `_build_parse_diagnostics()`

Builds a `ParseDiagnostics` object from the raw CSV structure.

Reports:

- row width differences
- empty headers
- duplicate headers
- preamble/header position warnings
- encoding and delimiter metadata

---

# Developer Notes

This adapter intentionally avoids:

- pandas
- implicit type casting
- implicit null handling
- automatic datetime parsing

Reason:

The cleaning pipeline should stay explicit and deterministic.

---

# Current Limitations

Current implementation reports structural parser diagnostics, but does not yet perform:

- suspicious row classification
- footer row classification
- row quarantine
- header detection confidence scoring
- manual header row override

Those belong to later stages in the CSV improvement plan.
